# CI: what runs where

Three GitHub Actions workflows. Only `ci.yml` decides whether a commit is released.

| Workflow | Trigger | Gates the release | Contents |
|---|---|---|---|
| `.github/workflows/ci.yml` | push to master, pull requests | yes (`release-tag` needs every job) | Go vet/test, agents (infra macOS/Windows, Go, PHP, Node, Python, Java, .NET), web typecheck/lint/Vitest/build, Helm, shellcheck/actionlint, release dry run (packages, `install.sh`). `make e2e` runs on master pushes with `continue-on-error` |
| `.github/workflows/long-tests.yml` | push to master (not docs-only), nightly 02:17 UTC, manual | no | the long Docker suites below |
| `.github/workflows/release.yml` | started by `release-tag` for a new tag, or manually | — | builds, signs and publishes the release ([releasing.md](releasing.md)) |

## long-tests.yml

The jobs run in parallel on `ubuntu-24.04`. A newer push cancels a running push run; scheduled and manual runs are not
cancelled.

| Job | Runs | Needs | Takes about |
|---|---|---|---|
| `go-integration` | `test/integration/run.sh shared`, `self`, `renderer` | Docker; see below | 25–40 min |
| `web-playwright` | `npx playwright test` (`web/playwright.config.ts`: Vite dev server with MSW mocks, no backend) | Node 22, Chromium from `npx playwright install` (the version of `@playwright/test` in `package-lock.json`) | 5–10 min |
| `updater-acceptance` | `make updater-acceptance` (`test/autoupdate`: 0.9.0 → 0.9.1, broken 0.9.2 rolled back, updater self-update) | Docker; images, local registry and a throwaway signing key are created by the test from the checked-out commit | 25–35 min |
| `install-server-test` | `sh packaging/test/install-server.sh` (docker:dind: install 0.1.6, re-run, upgrade to the latest stable release, downgrade refused) | internet access to GitHub releases and ghcr.io | 15–25 min |
| `tls-e2e` | `make tlstest` (compose `openlog-tlstest`; certificates generated by the test under `/tmp`) | Docker; builds `openlog:tlstest` | 15–25 min |
| `tiered-e2e` | `make tieredtest` (compose `openlog-tiered`: MinIO + 2×2 ClickHouse) | Docker | 15–20 min |
| `sso-e2e` | `make ssotest` (compose `openlog-ssotest`: PostgreSQL + Keycloak with `test/integration/sso/realm-openlog.json`; back-channel logout through `host.docker.internal`) | Docker | 5–10 min |
| `report` | summary table of the job results; on scheduled runs the issue below | — | < 1 min |

Every job removes its compose projects with `down -v` in an `if: always()` step and prints container logs on failure.
Playwright uploads `playwright-report/` and `test-results/` (traces) as the artifact `playwright-report` when it fails.

### Integration packages

`test/integration/run.sh` (`make integration`, `INTTEST_PHASE=shared|self|renderer` for one part):

| Phase | Packages | Dependencies |
|---|---|---|
| `shared` | `internal/deletion`, `dataexport`, `usage`, `quota`, `oql`, `api`, `dashboard`, `savedview`, `operator`, `updatereq` | compose project `openlog-inttest` from `internal/usage/testdata/docker-compose.yml`: PostgreSQL 16 (`127.0.0.1:27441`, one database per package) and ClickHouse 25.8 with hostname `clickhouse` and `deploy/compose/clickhouse/openlog-cluster.xml` (`127.0.0.1:19010`, for `ON CLUSTER` DDL). The script sets `OPENLOG_TEST_POSTGRES_DSN` and `OPENLOG_TEST_CLICKHOUSE_ADDR` |
| `self` | `internal/store/postgres`, `alert`, `fleet`, `processor`, `apm` | each test starts and removes its own project (`openlog-pgtest`, `-alerttest`, `-fleettest` from `test/integration/*`, `openlog-shardtest` / `openlog-apmshard` from `testdata/shardtest`) |
| `renderer` | `internal/renderer/chrome` | image `openlog-renderer:inttest` (`docker build --target renderer`) |

Packages run one at a time. `INTTEST_KEEP=1` keeps `openlog-inttest`.

## Failure reporting

- Push and manual runs: the failed jobs are red in the run and in the `report` summary; nothing else.
- Scheduled runs: `report` opens the issue **long-tests failing** (or comments on the open one) with the run link and
  the failed jobs, and closes it when a later scheduled run passes.
- A long-tests failure never blocks `release-tag`. Fix it on master; the next push or nightly run re-checks.

## Running locally

Docker with Compose v2.17+, Go (version of `go.mod`), Node ≥ 20.19 for the web suite.

```sh
make integration                 # or INTTEST_PHASE=shared make integration
make web-e2e                     # Playwright with MSW mocks
make updater-acceptance
sh packaging/test/install-server.sh [VERSION]
make tlstest
make tieredtest
make ssotest                     # SSOTEST_KEYCLOAK_PORT=27480 when 18080 is taken (e2e stack)
make e2e                         # E2E_UI=1 adds the Playwright phase against the stack (e2e.md)
```

What the e2e, TLS and tiered tests assert: [e2e.md](e2e.md).
